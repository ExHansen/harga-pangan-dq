# M3 — Checks, Incidents, GitHub Issues

**Status:** Implemented (2026-11-13)

## What was done

### 1. Seven Data Quality Checks

Created `src/hpdq/checks/` package with seven checks:

| # | Check | File | Severity | Scope |
|---|-------|------|----------|-------|
| 1 | Freshness | `freshness.py` | Warning/Critical | `commodity_date` |
| 2 | Completeness | `completeness.py` | Warning/Critical | `province`, `commodity_date` |
| 3 | Validity | `validity.py` | Critical | `cell`, `commodity_date` |
| 4 | Duplicates | `duplicates.py` | Warning/Critical | `cell`, `commodity_date` |
| 5 | Schema Drift | `schema_drift.py` | Critical | `snapshot` |
| 6 | Anomaly | `anomaly.py` | Warning/Critical | `cell` |
| 7 | Reconciliation | `reconciliation.py` | Warning/Critical | `province_day`, `commodity_date` |

### 2. Incident Store

Created `src/hpdq/checks/incidents_store.py` with SQLite store for append-only event logging:

- `log_event()` - Log events to database
- `get_open_incidents()` - Get all open incidents
- `resolve_incident()` - Mark incident as resolved
- `mark_false_alarm()` - Mark as false alarm
- `link_issue()` - Link to GitHub Issue
- `get_statistics()` - Get incident statistics

### 3. GitHub Issue Integration

Created `src/hpdq/checks/github.py` with GitHub Issue API:

- `open_issue()` - Open new issue
- `comment_issue()` - Add comment
- `close_issue()` - Close issue
- `add_label()` - Add label
- `get_issue()` - Get issue by number

### 4. CLI Command

Added `hpdq check` command to CLI:

```bash
# Run all checks for today
uv run hpdq check

# Run checks for specific date
uv run hpdq check --date 2026-11-12
```

### 5. GitHub Actions Workflow

Created `.github/workflows/incident-sync.yml`:

- Runs at 14:20 WIB and 17:20 WIB (Mon–Fri)
- Syncs open critical incidents to GitHub Issues
- Commits changes to `data` branch

### 6. Documentation

Created `docs/checks.md` with:

- Detailed description of all seven checks
- Incident store schema
- GitHub Issue labels and template
- Metrics and statistics

## How it works

```
┌─────────────────────────────────────────────────────────────────┐
│                     hpdq check command                           │
├─────────────────────────────────────────────────────────────────┤
│  1. Freshness     → 2. Completeness → 3. Validity               │
│  4. Duplicates    → 5. Schema drift → 6. Anomaly                │
│  7. Reconciliation                                           │
└─────────────────────────────────────────────────────────────────┘
                              ↓
                    Incident events (SQLite)
                              ↓
                    Critical → GitHub Issue
                              ↓
                    Auto-resolution for known patterns
```

## Running the checks

```bash
# Run all checks
uv run hpdq check

# Run with verbose output
uv run hpdq check --verbose

# Run for specific date
uv run hpdq check --date 2026-11-12
```

## Incident lifecycle

1. **Open**: Check detects issue
2. **Critical incidents**: Opened as GitHub Issues
3. **Auto-resolution**: Known patterns auto-resolved
4. **Resolved**: Manually or auto-resolved
